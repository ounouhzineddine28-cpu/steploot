# steploot

موقع أخبار تقنية بأربع لغات (العربية افتراضية RTL، الإنجليزية، الفرنسية، الإسبانية) — مبني بـ **Next.js 15 (App Router) + TypeScript + Tailwind CSS v4 + next-intl**.

## التشغيل

المتطلبات: Node.js 18.18 أو أحدث.

```bash
npm install
npm run dev
```

ثم افتح <http://localhost:3000> — سيوجَّه تلقائيًا إلى `/ar` (اللغة الافتراضية). للتأكد قبل النشر:

```bash
npm run build
```

## بنية المشروع

```
app/
  globals.css          ← ألوان وخطوط التصميم (Tailwind v4 عبر @theme — لا يوجد tailwind.config)
  [locale]/
    layout.tsx         ← <html dir/lang> + الخطوط + Header/Footer
    page.tsx           ← الرئيسية: Hero ← Trending News ← Extras & Crypto News
    products/ codes/ about/ privacy/ terms/
components/            ← مكوّن واحد لكل ملف (Header, Hero, TrendingNews, ExtrasCryptoNews, Footer, CodeTicket…)
i18n/ + middleware.ts  ← توجيه اللغات (ar افتراضية)
messages/*.json        ← كل النصوص — الملفات الأربعة بنفس المفاتيح دائمًا
lib/site.ts            ← رابط تيليجرام وروابط المنصات واسم الموقع (عدّلها هنا مرة واحدة)
```

## ربط المقالات بـ Supabase

المقالات (قسم "الأخبار الرائجة" في الرئيسية + صفحة `/article/[slug]`) تُقرأ من Supabase. قبل ربطه، الموقع يعرض تلقائيًا بيانات تجريبية محلية — ما ينكسر شيء.

**خطوات الربط:**

1. أنشئ مشروع مجاني على [supabase.com](https://supabase.com).
2. افتح **SQL Editor** داخل المشروع، وشغّل محتوى `supabase/schema.sql` كاملًا (مرة واحدة فقط). هذا ينشئ جدولين (`articles` و`article_translations`) و`view` باسم `published_articles` يقرأ منه الموقع.
3. (اختياري) شغّل `supabase/seed.sql` لإضافة مقال تجريبي بالأربع لغات، للتأكد من نجاح الربط.
4. من **Project Settings → API**، انسخ `Project URL` و`anon public key`.
5. انسخ `.env.local.example` إلى `.env.local` واملأ القيمتين:
   ```
   NEXT_PUBLIC_SUPABASE_URL=...
   NEXT_PUBLIC_SUPABASE_ANON_KEY=...
   ```
6. أعد تشغيل `npm run dev` — الموقع الآن يقرأ من Supabase بدل البيانات التجريبية.

**لإضافة/تعديل مقال:** من **Table Editor** داخل Supabase مباشرة — مافيه لوحة تحكم داخل الموقع حاليًا.
- أضف صف في جدول `articles` (التصنيف `category`، حالة `status` تبقى `draft` لين يصير جاهز، ثم غيّرها لـ `published`).
- أضف حتى 4 صفوف في `article_translations` (وحدة لكل لغة: `ar`/`en`/`fr`/`es`) مربوطة بـ `article_id`. تقدر تبدأ بلغة وحدة وتضيف الباقي بعدين — أي لغة ناقصة بس ما تظهر بذاك الموقع لين تضيفها.
- `slug` هو رابط المقال (`/article/<slug>`) — لازم يكون فريد لكل لغة.
- لما `status = 'published'`، المقال يظهر تلقائيًا في "الأخبار الرائجة" وعلى رابطه الخاص — بدون أي إعادة بناء (revalidate كل ساعة).

## الصور داخل المقالات

الصور تُرفع إلى **Supabase → Storage → media** (شغّل ملف SQL الخاص بالمخزن مرة واحدة أولًا)، ثم تنسخ رابط الصورة وتضعه داخل حقل `content` في `article_translations` بهذه الصيغة — في أي مكان بين الفقرات وبأي عدد:

```
![وصف الصورة](الرابط)              صورة بعرض النص
![وصف الصورة|wide](الرابط)         أعرض قليلًا
![وصف الصورة|full](الرابط)         بعرض الصفحة كاملًا

![الأولى](رابط1)
![الثانية](رابط2)                  سطران متتاليان = شبكة صور جنبًا إلى جنب
```

**الأكواد داخل المقال** — تكتبها بنفسك في النص، وتظهر بهدوء داخل الجملة (خط أحادي، ذهبي، تحته خط منقّط، والضغط عليها ينسخها):

```
وككل أسبوع، كود هذا المقال هو ((TMWEEK26)) — اضغط عليه لنسخه.
```

بلا بطاقات ولا لافتات داخل نص المقال. تصميم "التذكرة" محفوظ لصفحة `/codes` الأرشيفية فقط.

بقية صيغ المقال (كلها اختيارية، الفقرات تُفصل بسطر فارغ):

| الصيغة | النتيجة |
|---|---|
| نص عادي | فقرة — تدعم `**عريض**` و`` `كود` `` و`[نص](رابط)` |
| `## عنوان` / `### عنوان` | عنوان فرعي |
| `> اقتباس` | اقتباس بخط جانبي |
| `- عنصر` | قائمة نقطية |
| `---` | فاصل |
| `[اسم المنتج](aff:https://...)` | رابط شراء/أفلييت — يُضاف له `rel="nofollow sponsored"` تلقائيًا |

صورة الغلاف (أعلى المقال) تُوضع في عمود `cover_image_url` في جدول `articles` — رابط مجرّد بدون صيغة.

نصيحة: استخدم WebP بعرض 1200px، ولا تترك وصف الصورة فارغًا (مهم للـ SEO).

## لوحة التحكم وتعديل نصوص الصفحات

بعد تشغيل ملف SQL الخاص باللوحة والنصوص:

1. **Authentication → Users → Add user** (بريد + كلمة مرور، فعّل Auto Confirm)
2. انسخ الـ UUID وأضفه: `insert into public.admins (user_id, note) values ('UUID','المالك');`
3. **Authentication → Email**: أوقف تسجيل المستخدمين الجدد
4. ادخل على `/ar/admin`

اللوحة تدير **اللغات الأربع كلها** (واجهتها بالعربية فقط)، وفيها أربعة تبويبات:

- **المقالات** — إنشاء وتعديل وحذف، بتبويب لكل لغة، وحالة مسودة/منشور.
  المحرّر فيه:
  - **شريط أزرار** للتنسيق: عنوان، عنوان صغير، عريض، قائمة، اقتباس، رابط، كود، فاصل — تكتب الصيغة عنك
  - **إدراج الصور** في أي موضع: ضع المؤشر مكانها ثم اضغط «+ صورة» (أو الصق Ctrl+V أو اسحب الملف)
  - **شبكة صور**: ارفع عدة صور دفعة واحدة فتظهر جنبًا إلى جنب
  - **حجم الصورة**: عادية / عريضة / كاملة قبل الإدراج
  - **مكتبة الصور**: تصفّح كل الصور المرفوعة سابقًا وأدرج أيها بضغطة
  - **معاينة حيّة** بجانب النص، بنفس شكل صفحة المقال تمامًا
- **المنتجات** — إضافة وتعديل وحذف منتجات الأفلييت: السعر، رابط الشراء، صورة المنتج (رفع مباشر)، الترتيب، والاسم والوصف لكل لغة. تظهر في صفحة `/products` عند اختيار «منشور».
- **الصفحات** — تحرير «من نحن» و«سياسة الخصوصية» و«شروط الاستخدام» بمحرّر كامل (عناوين، قوائم، صور) وبأربع لغات.
- **نصوص الواجهة** — كل نص آخر في الموقع (القوائم، الرئيسية، الفوتر، الأزرار…) مع بحث بالمفتاح.

النصوص محفوظة في جدول `site_content` وتتجاوز ملفات `messages/*.json` (التي تبقى كقيم افتراضية). القيمة الفارغة = ارجع للنص الافتراضي. أي تعديل يظهر في الموقع خلال **10 دقائق** بدون إعادة نشر.

## قسم "إضافات وأخبار الكريبتو"

بعد تشغيل ملف SQL الخاص بالقسم:

- **أخبار العملات الرقمية** = مقالاتك المنشورة التي تصنيفها `crypto` — تظهر تلقائيًا وتفتح عند الضغط.
  اكتب المقال من اللوحة، وضع `category = crypto`، و`الشارة = BTC` مثلًا.
  لتغيير التصنيف المستخدم: `app_config` → المفتاح `crypto_category`.
- **رابط تيليجرام** — من `app_config` → `telegram_url` (يُستخدم في الهيدر والهيرو والقسم والفوتر معًا).
- **المنصات الأخرى** — جدول `platforms`: أضف صفًا لأي منصة (`key` + `label` + `url`)، ورتّبها بـ `sort_order`.
  الرابط الفارغ أو `enabled = false` يعني أن الزر لا يظهر — بدل أزرار لا تفتح شيئًا.

## قراءة المقال

نص المقال يظهر مقتطعًا عند ~14 سطرًا، ومع كل ضغطة على زر **قراءة المزيد** تنكشف 20 سطرًا إضافيًا. النص كامل موجود في الصفحة دائمًا (مقصوص بصريًا فقط)، فجوجل يقرأ المقال كاملًا ولا يُعدّ ذلك إخفاءً للمحتوى.

لتغيير عدد الأسطر: `components/ExpandableArticle.tsx` ← الخاصيتان `initialLines` و`step`.

## الوضع الليلي

زر التبديل (🌙 / ☀️) بجانب اختيار اللغة مباشرة — فيظهر في كل صفحات الموقع تلقائيًا. وفي صفحة المقال ولوحة التحكم (حيث لا يوجد مبدّل لغة) يظهر بمفرده.

- عند أول زيارة يتبع إعداد نظام الزائر تلقائيًا
- اختياره يُحفظ في متصفحه ويبقى في الزيارات القادمة
- لا توجد ومضة بيضاء عند التحميل — الثيم يُطبَّق قبل أول رسم للصفحة
- الألوان الليلية دافئة أيضًا (أسود مائل للبني) وليست زرقاء باردة، حفاظًا على هوية الموقع
- اللوحة `/ar/admin` تتبع الوضع نفسه تلقائيًا

لتعديل الألوان الليلية: `app/globals.css` ← قسم `.dark` في نهاية الملف.

## أين تعدّل؟

- **رابط تيليجرام والمنصات الأخرى:** `lib/site.ts` (حاليًا placeholders).
- **النصوص/الترجمات:** من لوحة التحكم أو جدول `site_content` مباشرة (بدون إعادة نشر). ملفات `messages/*.json` هي القيم الافتراضية فقط — أي **مفتاح جديد** يُضاف للملفات الأربعة معًا ثم إلى `site_content`.
- **الألوان والخطوط:** `app/globals.css` داخل `@theme` — الثيم الحالي أبيض/بيج دافئ مع أخضر عميق للروابط وذهبي للأكواد والأسعار.
- **هوية صفحة المقال وحدها:** `app/[locale]/(reader)/layout.tsx` — مستقلة عن باقي الموقع.
- **المقالات:** من Supabase مباشرة (فوق) — منطق القراءة في `lib/articles.ts`.
- **البيانات التجريبية المتبقية** (الكريبتو، الأكواد، المنتجات): مصفوفات داخل المكوّن/الصفحة نفسها، مقسّمة حسب اللغة — استبدلها ببيانات حقيقية لاحقًا.

## ملاحظات مهمة

- صفحتا `privacy` و`terms` نصوص مؤقتة — **يجب** استبدالها بمحتوى حقيقي قبل التقديم على AdSense.
- صفحة `/codes` موجودة كأرشيف لكنها **غير مربوطة من الرئيسية** عمدًا (حسب AGENTS.md) — الأكواد تُوزَّع داخل المقالات.
- الخطوة الكبيرة التالية: صفحة المقال `/[locale]/article/[slug]` مع مكوّن الكود المخفي، ثم اختيار مصدر المحتوى (Notion أو Sanity). راجع `tasks.md`.
- التزم بقواعد `AGENTS.md` عند أي تعديل (خصائص RTL المنطقية، مزامنة ملفات الترجمة، حدود الإعلانات…).

## النشر وربط الدومين

المشروع يحتاج بيئة تشغيل Node (بسبب `middleware.ts` لتوجيه اللغات) — يعني **لا** يعمل على استضافة ملفات ثابتة بحتة. الأسهل: Vercel.

**1) ارفع المشروع على GitHub**

```bash
git init
git add .
git commit -m "steploot"
git branch -M main
git remote add origin https://github.com/<حسابك>/techmaster.git
git push -u origin main
```

`.gitignore` يستثني `node_modules` و`.next` و`.env.local` تلقائيًا — لا ترفع مفاتيحك أبدًا.

**2) انشر على Vercel**

- vercel.com → **Add New → Project** → اختر المستودع (يكتشف Next.js تلقائيًا، لا تغيّر أي إعداد)
- قبل الضغط على Deploy، أضف متغيّرات البيئة في **Environment Variables**:

| المتغيّر | القيمة |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | من Supabase → Project Settings → API |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | نفس المكان (المفتاح `anon public`) |
| `NEXT_PUBLIC_SITE_URL` | رابط موقعك النهائي، مثلًا `https://techmaster.com` |

> هذه المتغيّرات تُقرأ **وقت البناء** — أي تعديل عليها يتطلّب **Redeploy** ليأخذ مفعوله.

**3) اربط الدومين**

- في Vercel: **Project → Settings → Domains → Add** واكتب الدومين
- Vercel يعرض لك سجلّات DNS الخاصة بمشروعك — استخدم القيم المعروضة عندك (القيم العامة `A @ → 76.76.21.21` و`CNAME www → cname.vercel-dns.com` ما زالت تعمل)
- أضف السجلّين عند مزوّد الدومين، واحذف أي سجل `A` قديم لـ `www` إن وُجد
- إذا كان الدومين على Cloudflare: اجعل السحابة **رمادية (DNS only)** وليس برتقالية، وإلا تفشل شهادة SSL
- الانتشار من دقائق إلى ساعات، وشهادة HTTPS تُصدر تلقائيًا

**4) بعد ربط الدومين**

- عدّل `NEXT_PUBLIC_SITE_URL` للدومين الحقيقي ثم **Redeploy**
- تأكد أن `/sitemap.xml` و`/robots.txt` يظهران بالدومين الصحيح
- أضف الموقع إلى **Google Search Console** وأرسل رابط `sitemap.xml`

**تنبيه مهم — Supabase المجاني:** المشاريع المجانية تُوقَف تلقائيًا بعد أسبوع بلا نشاط قاعدة بيانات (البيانات تبقى محفوظة ويمكن استئنافها يدويًا). زيارات حقيقية للموقع تكفي لإبقائه نشطًا؛ وإن توقّفت الزيارات فترة، استأنفه من لوحة Supabase أو رقِّ للخطة المدفوعة.
